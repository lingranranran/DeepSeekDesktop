# DeepSeek Harness Desktop

> **`dsh web` 的全部能力，一个原生窗口，零命令行。**

将 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）的 Web UI 封装为 Windows 原生桌面应用：前端零改动，100% 保留 Web UI 能力，叠加托盘、通知、服务托管等桌面体验。

| 项目属性 | 说明 |
|---|---|
| 目标平台 | Windows 10+（架构预留跨平台能力） |
| 技术栈 | Electron · TypeScript · @deepseek-ai/dsh |
| 适配 dsh 版本 | `0.1.0-rc.6`（版本锁定，随应用发版升级） |
| dsh 运行时 | 内置 Node.js v22.23.2（22 LTS）+ dsh 0.1.0-rc.6，开箱即用 |
| 许可证 | MIT |

> **当前状态**：M0–M7 已完成；当前版本 v0.4.0。v0.2.0 起支持自动更新（GitHub Releases + blockmap 差量下载）与 tag 触发的自动发布流水线；内置运行时以单文件 tar 分发：安装秒级完成，首次启动时解压到用户数据目录并显示进度。v0.3.0 起 dsh 运行时可独立于应用升级（清单发现 + 下载校验 + 一键切换/回滚 + 新版本提醒）；v0.4.0 起提供桌面通知桥（任务完成 / 权限审批原生通知，点击聚焦窗口）与设置页诊断区（日志查看 / 诊断包导出）。
> 注意：dsh 处于开发者预览（Developer Preview）阶段，存在破坏性变更，本项目采用版本锁定策略跟随上游。

第三方声明：本项目为社区驱动的开源封装项目，与 DeepSeek AI 官方无隶属关系。

## 1. 项目概述

### 1.1 背景

DeepSeek Harness（`dsh`）是 DeepSeek AI 开源的 Agent Harness（智能体框架），遵循"一切皆插件"（Everything is a Plugin）的架构理念，由 Cordis 微内核驱动。其官方交互入口是：

```bash
npx @deepseek-ai/dsh web
```

该命令在本地启动 HTTP 服务（默认 `http://127.0.0.1:3080`）并通过浏览器访问 Web UI。作为日常桌面工具使用时存在痛点：

- 必须先安装 Node.js（≥ 22.19）并掌握命令行启动方式
- 以浏览器标签页形态存在，易被日常浏览淹没，关闭标签页后缺乏常驻入口
- 缺少系统级集成：无托盘、无任务完成通知、无全局快捷键
- 服务进程的启动、停止、异常恢复需要用户自行管理

### 1.2 目标

做一个**忠实的桌面化封装**：

- **能力完整**：dsh Web UI 的全部功能（会话、Agent、工具调用、审批、插件、轨迹回放）原样保留，前端零改动
- **开箱即用**：内置 Node.js 运行时与 `@deepseek-ai/dsh`，用户无需安装任何前置依赖
- **桌面体验**：独立窗口、系统托盘、任务通知、全局快捷键、窗口状态记忆
- **服务托管**：dsh 服务随应用自动启动、健康检查、崩溃自动恢复、退出自动清理

### 1.3 非目标（v1 范围外）

- 不修改 dsh 内核及其 Web UI 源码（仅封装，不 fork 功能）
- 不支持 macOS / Linux（架构上不做限制，留待后续版本）
- 不做多实例（单实例锁，重复启动唤起已有窗口）
- 不做去端口化的进程内 IPC 通信（远期方向，见路线图）

| 工作区 | 选择工作区目录、文件读写、终端执行、Web 搜索 |

| 自动更新 | 启动后静默检查 GitHub Releases，发现新版本后台差量下载，就绪后通知一键重启安装（v0.2.0+） |

## 3. 技术架构

### 3.1 总体架构

```text
┌──────────────────────────────────────────────────────┐
│               DeepSeek Harness Desktop                │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │           Electron 主进程（Node.js）            │  │
│  │  · 单实例锁（requestSingleInstanceLock）        │  │
│  │  · dsh 生命周期管理（spawn / 健康检查 / 重启）   │  │
│  │  · 端口协商（--port 0 + stdout 解析）            │  │
│  │  · 托盘 / 全局快捷键 / 系统通知                  │  │
│  │  · 日志                                        │  │
│  └───────────────┬────────────────────────────────┘  │
│                  │ spawn + stdout 端口回传             │
│  ┌───────────────▼────────────────────────────────┐  │
│  │      dsh 服务子进程（内置 Node.js ≥ 22.19）     │  │
│  │      dsh web --port 0 --no-open                 │  │
│  │      监听 http://127.0.0.1:<随机端口>            │  │
│  └───────────────┬────────────────────────────────┘  │
│                  │ HTTP（仅回环地址）                   │
│  ┌───────────────▼────────────────────────────────┐  │
│  │      BrowserWindow 渲染进程（Chromium）          │  │
│  │      loadURL(http://127.0.0.1:<随机端口>)        │  │
│  │      = 完整的 dsh Web UI（零改动）               │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

### 3.2 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | Electron | 纯 JS/TS 技术栈、生态最成熟、渲染行为与 Chrome 浏览器一致（对 dsh Web UI 的兼容性风险最低） |
| dsh 集成方式 | 完全内置 | 用户零配置开箱即用；代价是安装包体积增大（约 150 MB）与 dsh 升级需随应用发版 |
| 端口策略 | `--port 0` 随机端口 | 避免与用户已运行的 dsh 实例或其他应用冲突；从子进程 stdout 解析实际端口 |
| 进程模型 | 独立子进程 spawn | dsh 与桌面壳解耦，任一方崩溃互不传染，升级互不干扰 |
| 前端策略 | 直接加载 dsh Web UI | 零改动即获得 100% 能力，并自动跟随官方 UI 迭代 |
| Node 运行时 | 随包分发独立 Node.js v22.23.2（22 LTS） | dsh 要求 Node ^22.19 或 ≥ 24；独立运行时与 Electron 内嵌 Node 版本解耦，规避版本漂移风险 |
| 安装程序 | NSIS 引导式（oneClick: false） | 支持自定义安装目录；按用户安装无需管理员权限；暂不签名（接受 SmartScreen 提示） |

### 3.3 启动时序与生命周期

**启动（冷启动）：**

1. 单实例检查：`app.requestSingleInstanceLock()`，已有实例则聚焦其主窗口后退出
2. 就绪页：创建窗口并显示轻量加载页（原生渲染，不依赖 dsh）
3. 运行时就绪（v0.1.1+）：首次启动将安装目录内的单文件 `node-runtime.tar`（约 340 MB，内含 Node.js 与 dsh）解压到 `userData/runtime`，加载页实时显示进度；后续启动校验标记直接复用（毫秒级）。解压被意外中断时，下次启动自动检测并完整重做（自愈）
4. 拉起服务：以内置 Node 运行时 spawn dsh（`web --port 0 --no-open`）；Windows 下直接以 `node <dsh-bin>.js` 方式调用，绕过 `.cmd` shim，避免 shell 解析问题
5. 端口发现：解析子进程 stdout 中的 `dsh web: http://127.0.0.1:<port>` 获取实际端口
6. 加载 UI：`BrowserWindow.loadURL()` 载入 Web UI
7. 健康守护：周期性健康检查，异常自动重启（上限 3 次），超限显示错误页并给出日志路径

**退出（优雅关闭）：**

1. 主窗口关闭时，依据托盘配置决定隐藏到托盘或进入退出流程
2. 退出流程：向 dsh 子进程发送终止信号，等待其优雅退出
3. 超时（约 5 秒）未退出时，Windows 下以 `taskkill /PID <pid> /T /F` 强制回收整棵进程树
4. 校验无残留监听端口后结束应用

### 3.5 数据与配置

| 数据 | 位置 | 说明 |
|---|---|---|
| dsh 数据（会话、配置、插件） | `%USERPROFILE%\.dsh`（可用 `DSH_HOME` 覆盖） | 与命令行 dsh 完全共享互通 |
| dsh 的 API Key | 由 dsh 自身存储于 `~/.dsh` | 桌面端不经手、不复制、不二次存储 |
| 桌面应用自身配置 | Electron `userData` 目录 | 托盘行为、快捷键、开机自启等 |

### 3.6 安全边界

- dsh 服务仅监听 `127.0.0.1` 回环地址，不暴露于局域网
- 与直接使用 `dsh web` 相同的信任模型：本机任意进程均可访问该端口（浏览器直连场景同样如此）；敏感操作仍受 dsh 自身的审批机制约束
- 渲染进程启用 Electron 安全默认值（`contextIsolation` 开启、`nodeIntegration` 禁用）

## 4. 安装指南

### 4.1 用户安装

从项目的 `release/` 目录获取 `DeepSeek-Harness-Desktop-Setup-<版本号>.exe`（NSIS 引导式安装程序）：

1. 双击运行安装程序。Windows SmartScreen 可能提示"已保护你的电脑"（因未购买代码签名证书）——点击 **更多信息 → 仍要运行** 即可继续
2. 选择安装目录（默认 `%LOCALAPPDATA%\Programs\DeepSeek Harness Desktop`，按用户安装无需管理员权限）
3. 安装完成后自动创建桌面快捷方式与开始菜单项（快捷方式名 **DeepSeek Harness**）
4. **首次启动**会自动准备运行环境：将内置的 Node.js 与 dsh 解压到用户数据目录（约 1–3 分钟，窗口内有进度条，仅需一次），随后自动进入应用；**之后启动**直接就绪
5. 无需安装 Node.js 或任何其他前置依赖；卸载经"设置 → 应用"或开始菜单卸载项进行，卸载时可选择是否保留应用数据（保留则重装后无需再次解压运行时）

> dsh 的会话与配置数据存放在 `~/.dsh`，与安装目录无关，卸载/重装应用不会丢失。

### 4.2 从源码构建与运行

前置要求：

- Windows 10 及以上
- Node.js ≥ 22.19（或 ≥ 24），用于开发
- pnpm 11+（`npm i -g pnpm` 或通过 corepack 启用）
- Git

```bash
# 1. 克隆仓库（仓库地址待项目初始化后确定）
git clone https://github.com/<your-org>/deepseek-harness-desktop.git
cd deepseek-harness-desktop

# 2. 安装依赖（store/cache 已配置在 pnpm-workspace.yaml，指向项目内目录）
pnpm install

# 3. 准备内置运行时（下载 Node v22.23.2 zip + sha256 校验 + 全局安装 dsh@0.1.0-rc.6
#    到 resources/node-runtime/；已就绪时自动跳过，--force 强制重建）
pnpm prepare-runtime

# 4. 开发模式运行（开发模式无内置运行时，回退使用系统 Node 与全局/本地 dsh）
pnpm dev

# 5. 仅编译 TypeScript（输出 dist/）
pnpm build

# 6. 构建 Windows 安装程序（编译 + 准备运行时 + electron-builder NSIS，
#    产物输出至 release/：Setup exe、blockmap、win-unpacked 免安装目录）
pnpm dist
```

> **构建细节**：`pnpm dist` 会将 `resources/node-runtime.tar`（prepare-runtime 生成的单文件归档，内含 Node + dsh）作为 extraResources 打入安装包 asar 之外的 `resources\`。v0.1.0 曾直接散装 3 万+ 运行时文件，在 Windows Defender 实时扫描下 NSIS 逐文件解压形似卡死；v0.1.1 起安装只需写入一个大文件（秒级完成），应用首次启动时再解压到 `userData/runtime`（见 [electron/runtime-setup.ts](electron/runtime-setup.ts)）。首次构建会联网下载 Electron 发行包与 NSIS 工具链（约 200 MB，有缓存）。
>
> 开发模式下如本机已装有 dsh，注意端口策略：桌面端使用随机端口，不会与你正在运行的 `dsh web`（默认 3080）冲突；两者共享 `~/.dsh` 数据目录。

## 5. 使用方法

> 全部路线图功能已交付（M0–M7）。

### 5.1 首次启动

1. 双击应用图标启动。首次启动会自动准备运行环境（解压内置 Node.js 与 dsh，窗口内显示进度，约 1–3 分钟，仅需一次），随后自动初始化 dsh（首次运行会自动创建 `~/.dsh` 数据目录与 web profile）
2. 进入 Web UI 后打开 **设置 → 模型**，填入 DeepSeek API Key（或 OpenAI 兼容网关地址）
3. 点击 **选择工作区**，添加并选中你的项目目录（选中工作区前输入框不可用，属 dsh 正常行为）
4. 发送第一条任务，开始使用

### 5.2 日常使用

| 操作 | 行为 |
|---|---|
| 点击窗口关闭按钮 | 默认最小化到系统托盘（可在设置中改为直接退出） |
| 托盘图标 → 主面板 | 显示 / 隐藏主窗口 |
| 托盘图标 → 退出 | 优雅关闭 dsh 服务并退出应用 |
| 全局快捷键 | 从任意应用唤起窗口（默认关闭，设置中开启） |
| 桌面通知 | Agent 完成任务或发起权限审批时弹出系统通知（仅窗口未聚焦时；点击通知聚焦主窗口，可在设置中关闭，v0.4.0+） |

### 5.3 与命令行 dsh 协作

桌面端与命令行 dsh 共享同一份数据目录（`~/.dsh`）：

- 白天用桌面端聊到一半，晚上可以直接 `dsh web` 或其他 dsh 客户端继续同一批会话，反之亦然
- 两者的差别仅在交互外壳，会话、配置、插件数据完全互通

### 5.4 日志与排障

日志文件位于 Electron `userData/logs/` 目录（设置页提供"打开日志目录"入口），包含主进程事件与 dsh 的 stdout/stderr 转发。v0.4.0 起设置页内置**诊断区**：日志尾部查看器（免翻文件即可排查）与一键导出诊断包（日志 + 应用 / 运行时版本信息打包，便于 Issue 附带）。

## 8. 常见问题解答（FAQ）

**Q1：和直接用浏览器访问 `dsh web` 有什么区别？**

核心能力完全一致（加载的就是同一份 Web UI）。区别在外壳：无需命令行与 Node 环境、独立窗口不与浏览器标签页混杂、托盘常驻、任务完成通知、全局快捷键，以及服务生命周期全自动托管。

**Q2：端口被占用了怎么办？**

桌面端以 `--port 0` 启动 dsh，由操作系统分配随机空闲端口，不存在固定端口冲突问题。

**Q3：我的会话数据存在哪里？会丢吗？**

数据由 dsh 管理于 `~/.dsh`（Windows 为 `%USERPROFILE%\.dsh`），与命令行 dsh 完全互通。卸载桌面应用不影响该目录。

**Q4：如何升级内置的 dsh？**

dsh 随应用版本一同分发，升级 dsh 即升级应用。由于 dsh 处于开发者预览阶段（存在破坏性变更），本项目采用版本锁定策略：内置版本定义在 `scripts/prepare-runtime.mjs` 的 `DSH_VERSION` 常量（当前 `0.1.0-rc.6`），每个应用版本在发布说明中标注适配的 `@deepseek-ai/dsh` 版本。

**Q5：启动后白屏 / 一直加载怎么办？**

依次检查：打开日志目录查看 dsh stdout/stderr；确认 API Key 与工作区已完成首次配置；重启应用（会自动重新拉起 dsh 服务）；仍异常时提交 Issue 并附日志。

**Q6：安全方面需要注意什么？**

dsh 仅监听 `127.0.0.1`，不暴露局域网；但与本机其他进程共享信任边界（与浏览器直连 `dsh web` 相同）。Agent 的敏感操作（文件写入、命令执行等）受 dsh 自身审批机制约束。请遵循 dsh 官方安全说明，在可信工作区中使用。

**Q7：支持哪些模型？**

模型接入由 dsh 决定：DeepSeek 官方模型、OpenAI 兼容网关，以及经插件接入的本地模型。桌面端不对此做任何限制。

**Q8：为什么安装包这么大？首次启动为什么还要等一会儿？**

完全内置方案打包了 Electron（Chromium）、独立 Node.js 运行时与 dsh 及其依赖，安装包约 130 MB。安装本身只需数秒（运行时以单文件归档分发）；首次启动会将运行时解压到用户数据目录（约 1–3 分钟，有进度条），之后启动直接就绪。这是"零配置开箱即用"的代价，已在方案选型时确认接受。

**Q9：之后会支持 macOS / Linux 吗？**

架构上不做平台绑定（Electron 天然跨平台），但 v1 只测试与发布 Windows 版本，跨平台排在远期路线。

**Q10：自动更新是怎么工作的？**

应用启动约 15 秒后静默查询 GitHub Releases 的 `latest.yml`；发现新版本即在后台差量下载（只传输变更块），完成后弹系统通知，点击即优雅停止 dsh 并重启安装。也可在 **设置 → 当前版本 → 检查更新** 手动触发。v0.1.x 无此机制，升级到 v0.2.0 仍需手动安装一次，此后即可自动更新。
